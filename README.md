# Horizon

An Android driving game about the experience of driving through a beautiful open world — no lap
times, no pressure. Mountain passes, cities, country roads and highway, one seamless world, warm
stylized low-poly art. See [CLAUDE.md](CLAUDE.md) for the full concept and working conventions.

**Status:** prototype scaffolding. The Unity project lives at the repo root and the scripts are
complete. The prototype scene is generated by a menu command (step 3 below).

## Setup

### 1. Install Unity

1. Install [Unity Hub](https://unity.com/download).
2. Install **Unity 6.3 LTS — exactly `6000.3.21f1`**, Apple Silicon build. This is the version the
   project is pinned to in `ProjectSettings/ProjectVersion.txt`. LTS is supported into December 2027;
   the tech-stream releases (6.4, 6.5, …) are only maintained for a few months, which is the wrong
   trade for a project you intend to live in.
3. In the module list tick **Android Build Support**, including its **OpenJDK** and
   **Android SDK & NDK Tools** sub-modules. This is the whole Android toolchain — no separate JDK or
   Android SDK install is needed.

### 2. Open the project

The project is the repo — `Assets/`, `Packages/` and `ProjectSettings/` are committed. In Unity Hub
choose **Add > Add project from disk** and select this folder. `Library/`, `Logs/`, `Temp/` and
`UserSettings/` are generated on first open and are git-ignored.

Nothing needs configuring. Active Input Handling is already *Input System Package*, Asset
Serialization is already *Force Text*, and Version Control Mode is already *Visible Meta Files* — the
last two are what keep scenes and prefabs reviewable and mergeable in git.

URP is wired with two quality tiers out of the box: the **Mobile** level uses `Mobile_RPAsset` and is
excluded on desktop, the **PC** level uses `PC_RPAsset`. Android therefore picks the mobile tier by
itself, which is the foundation M5 builds on.

> **If you ever recreate this project from the Unity template:** the `Universal 3D` template bundled
> with `6000.3.21f1` pins package versions *below that editor's own minimums* — Input System 1.12.0
> against a minimum of 1.20.0, URP 17.0.1 against 17.3.0. Unity Hub silently bumps them during
> project creation; unpacking the template by hand does not, and Input System 1.12.0 then fails to
> compile with `error CS0117: 'BuildTarget' does not contain a definition for 'ReservedCFE'`. The
> versions in `Packages/manifest.json` are the editor's own minimums, taken from
> `Unity.app/Contents/Resources/PackageManager/Editor/manifest.json`.

Optional, for authoring roads with scene-view handles later: add **Splines** (2.9.0 for this editor)
via **Window > Package Manager > Unity Registry**. The prototype does not need it — the Splines
adapter sits in its own conditionally-compiled assembly and stays dormant until the package appears.

`Assets/InputSystem_Actions.inputactions`, `Assets/Readme.asset` and `Assets/TutorialInfo/` are
leftover template content and can be deleted; nothing references them.

### 4. Build the prototype

**Tools > Horizon > Rebuild Prototype Scene**

Two scenes are generated. **`Bootstrap.unity` is intentionally almost empty** — one object holding
the input router, the frame-rate policy and the debug overlay, with no camera and no geometry. If you
open it on its own the scene view looks blank and the game view is black; that is correct. The world
is loaded additively, so press **Play** to see anything, or open `World_MountainPass.unity` to look
at the road in the editor. The rebuild leaves both scenes open, which is the state to work in.

This generates everything: the mountain-pass road and terrain meshes, materials, the vehicle prefab,
both scenes, and the build-settings entries. Then press **Play**.

Re-running it is safe. Configs (`VehicleConfig_Prototype`, `TimeOfDayProfile_Default`) and materials
are only created if missing, so hand-tuned values survive a rebuild. Meshes, the prefab and the
scenes are derived output and always regenerated.

## Driving it

| Input | Action |
|---|---|
| `W` / `↑` | throttle |
| `S` / `↓` | brake, and reverse once stopped |
| `A` `D` / `←` `→` | steer |
| `Space` | handbrake |
| Gamepad | left stick steers, triggers drive |

The debug overlay (Editor and development builds only) shows speed, the active control scheme, and a
time-of-day slider. **Next control scheme** cycles through keyboard, tilt, touch-steer and
touch-buttons; the two touch schemes are usable on desktop via the mouse, so all four can be
compared without a device. Tilt needs real hardware to judge — the Device Simulator does not feed
sensor data.

Tuning happens in `Assets/_Project/Settings/VehicleConfig_Prototype.asset`, editable while in Play
mode, with changes persisting.

## Installing a release

Built APKs are published on the [Releases page](https://github.com/rbatmaz69/Horizon/releases).
Open it on the phone, download `Horizon-<version>.apk` and tap it. Android asks once whether the
browser may install unknown apps — that permission is per-app and has to be granted before the
install proceeds.

ARM64 only, Android 7.1 (API 25) and newer. There is no 32-bit build, which no phone made in the
last several years needs.

## Cutting a release

```
export HORIZON_KEYSTORE_PASS=...
./Tools/release.sh 0.2.0
```

Or write the password once into `~/.horizon/keystore-password.txt` (`chmod 600`) and drop the
export — the script falls back to that file, which keeps the password out of your shell history.

That configures the Android player, builds a signed APK in batch mode, tags `v0.2.0`, pushes, and
attaches the APK to a GitHub release. It refuses to start on a dirty tree, a branch other than
`main`, an existing tag, a missing keystore or an open Unity editor — all of which are cheaper to
find out about before an IL2CPP build than after one.

Release builds are signed with a keystore kept outside the repo, generated once with the JDK that
ships inside Unity's Android module:

```
mkdir -p ~/.horizon
/Applications/Unity/Hub/Editor/6000.3.21f1/PlaybackEngines/AndroidPlayer/OpenJDK/bin/keytool \
  -genkeypair -v -keystore ~/.horizon/horizon-release.keystore \
  -alias horizon -keyalg RSA -keysize 2048 -validity 10000
```

**Back that file up.** Android identifies an app by its signature, so a release signed with a
different key cannot install over an existing one — losing the keystore means every player has to
uninstall before they can update.

The build happens on your machine rather than in GitHub Actions because most of `Assets/` is
generated geometry that git ignores; a CI checkout would get scenes referencing meshes that do not
exist there and would have to regenerate the world first.

## Layout

```
Assets/_Project/
  Art/Materials              generated placeholder materials
  Art/Models/Generated       road and terrain meshes (derived — do not hand-edit)
  Prefabs/Vehicles           Vehicle_Prototype
  Scenes                     Bootstrap, World_MountainPass
  Settings                   VehicleConfig, TimeOfDayProfile
  Scripts/
    Horizon.Core             ChaseCamera
    Horizon.Input            IDriveInput and the four control schemes
    Horizon.Vehicle          raycast-wheel vehicle model
    Horizon.World            road path, mesh generation, chunk/streaming boundary
    Horizon.World.Splines    optional Splines authoring adapter
    Horizon.Atmosphere       time of day, fog, weather layer
    Horizon.Game             scene wiring and debug overlay
    Horizon.EditorTools      the prototype setup tool
```

Dependencies between these point one way only — see the module layout section in
[CLAUDE.md](CLAUDE.md) before adding a reference.
